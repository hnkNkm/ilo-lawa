# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ilo-lawa is a minimal UEFI-based operating system kernel written in Rust that transitions from UEFI boot services to a standalone kernel environment. It implements custom interrupt handling, a heap allocator, a framebuffer terminal, an interactive shell, a RAM-based filesystem, a virtio-blk block-device driver with a read-only FAT32 layer (issue #14), and cooperative kernel tasks with round-robin scheduling (issue #18 stage 1 — no timer preemption yet).

## Development Commands

```bash
# Build the kernel (all builds must run inside the Nix environment)
make build
# equivalent to: nix develop --impure -c cargo build --release

# Run in QEMU (Linux with KVM)
make run

# Run in QEMU (macOS / no KVM)
make run-no-kvm

# Create the 64 MiB FAT32 data disk (disk.img, gitignored) that `run` /
# `run-no-kvm` attach as a virtio-blk device; (re)installs the test files
# HELLO.TXT and long_file_name_test.txt. Needs dosfstools + mtools (in the
# Nix dev shell since the storage work, issue #14).
make disk

# Build with the test harness and run it headless in QEMU (exit 33 = pass)
make test

# Clean build artifacts (also removes esp/ and ovmf/)
make clean

# Enter the Nix dev shell directly
nix develop --impure
```

Notes:
- `.cargo/config.toml` sets the default target to `x86_64-unknown-uefi` and enables `build-std` for `core`, `compiler_builtins`, and `alloc` — plain `cargo build` works inside the Nix shell without extra flags.
- `make run` copies the `.efi` to `esp/efi/boot/bootx64.efi` and boots QEMU with OVMF firmware (auto-downloaded to `ovmf/` on first run).
- `make test` is the automated test path: it builds with `--features test-harness` into a separate `target-test/` dir (so `make build`'s cache is untouched), boots headless QEMU with `-device isa-debug-exit,iobase=0xf4,iosize=0x04`, and maps the exit code — 33 (harness wrote 0x10) is pass; anything else (35 = harness reported failures, 124 = timeout, panic/hang) is failure. The full serial log lands in `test-serial.log` (gitignored).
- Without the feature there are no automated tests; verification is done by booting in QEMU and exercising the shell. The console is mirrored to COM1, so the serial output (`-serial stdio` in the Makefile, or `-serial file:...` headless) contains the full boot log and shell session as plain text; with serial RX enabled (#21), typing into the same `-serial stdio` channel feeds the shell, enabling fully headless sessions.
- Requires nightly Rust (provided by the Nix flake) for `#![feature(abi_x86_interrupt)]` and `#![feature(alloc_error_handler)]`.

## Architecture Overview

### Boot Process Flow
1. **UEFI Entry** (`src/main.rs`): Captures framebuffer info from GOP — base/width/height/stride plus the pixel format (kernel-owned `kernel::PixelFormat`: Bgr, Rgb, Bitmask with per-channel masks, BltOnly; captured before `ExitBootServices()` since the `uefi` crate type is unusable afterwards). A Blt-only GOP (no linear framebuffer) is refused here: message on the firmware stdout and `Status::UNSUPPORTED` before `kernel_main` ever runs. It also captures the ACPI RSDP physical address from `system_table.config_table()` (prefers `ACPI2_GUID`/XSDT-capable, falls back to `ACPI_GUID`; `0` when the firmware publishes no ACPI tables) — after `ExitBootServices()` the config table is gone, so this must happen before it. Then calls `ExitBootServices()`. After this point no UEFI services exist.
2. **Kernel Entry** (`src/kernel.rs:kernel_main`): Disables interrupts, then initializes in strict order: terminal → page tables (paging) → ACPI (`acpi::init` — needs the identity map, must stay heap-free) → memory map + frame allocator (`memory::init`) → heap allocator (sized from the frame pool) → PCI enumeration (`drivers::pci::init`) → storage (`drivers::virtio_blk::init`, needs heap + PCI table, non-fatal on failure, then `fs::fat32::mount`) → CPU features (FPU/SSE) → GDT → IDT → PIC → filesystem → PIT timer (100 Hz) → RTC wall-clock snapshot (`rtc::init`) → enable interrupts → task scheduler (`task::init` — needs the heap for task stacks) → shell. `memory::init` must run before heap init: the heap's frames are reserved out of the frame allocator's pool, and the frame summary/self-check must print for the untouched pool. Heap reservation must complete before filesystem/shell init — the first heap users. Filesystem init must stay before interrupt enable so no IRQ can arrive while its locks are held; the PIT is programmed after the PIC (IRQ0 routed) and before interrupts are enabled. Test builds only (feature `test-harness`): after the filesystem and PIT are up, `test_harness::run()` executes the kernel self-tests and exits QEMU via isa-debug-exit before interrupts are ever enabled — the shell, task scheduler, and main loop are not reached (the harness's `task_scheduler` test calls the idempotent `task::init()` itself).
3. **Runtime**: The keyboard ISR only enqueues raw scancodes (`keyboard::add_scancode` → `SCANCODE_QUEUE`); the serial ISR only enqueues COM1 bytes (`serial::service_rx_interrupt` → `RX_QUEUE`). The main loop in `kernel_main` drains BOTH queues in thread context — one scancode and one serial byte per iteration, `try_pop_scancode`/`try_pop_input` with interrupts disabled, `enable_and_hlt` when both are empty — so a backlog on one input cannot starve the other. Dispatch: scancode → `keyboard::KeyEvent`, byte → `serial::handle_input` (→ `KeyEvent`) → `shell::handle_key_event` → line editing / command execution. With BOTH queues empty, the main loop acts as the scheduler driver: if cooperative tasks are Ready (`task::has_ready_tasks`) it runs one `task::schedule()` round (which returns when the main task is running again); only when no other task is ready does it fall back to `enable_and_hlt`.

### Critical Components

**Interrupt Architecture**:
- `src/gdt.rs`: GDT with TSS; IST stack for double faults (`DOUBLE_FAULT_IST_INDEX`)
- `src/interrupts.rs`: IDT with CPU exception handlers (breakpoint, page fault, GPF, invalid opcode, double fault) and hardware IRQs (timer, keyboard). Timer ISR calls `time::tick()` (atomic increment) and sends EOI — nothing else.
- `src/pic.rs`: Legacy 8259 PIC (not APIC); handlers must send EOI

**Timer & Time** (`src/time.rs`):
- PIT 8253/8254 channel 0 programmed to 100 Hz (base 1,193,182 Hz, divisor 11,932, command 0x36 → port 0x43, divisor → port 0x40) by `time::init()`; tick = 10 ms.
- `static TICKS: AtomicU64` (`Ordering::Relaxed`) incremented by the timer ISR via `time::tick()`; readers: `ticks()`, `uptime_seconds()`.
- `sleep_ticks(n)` / `sleep_ms(ms)`: hlt-loop until the target tick — thread context with interrupts enabled ONLY (never from an ISR or with interrupts disabled). 10 ms resolution; `sleep_ms` rounds up to whole ticks, `ms == 0` returns immediately.
- Consumers: shell `uptime` command (days + HH:MM:SS) and `sleep <ms>` command.

**Wall Clock** (`src/rtc.rs`, issue #20):
- After ExitBootServices the UEFI Runtime `GetTime` service is gone, so the MC146818-compatible CMOS RTC behind ports 0x70/0x71 is the only calendar source; monotonic time stays in the PIT tick counter (`src/time.rs`).
- `rtc::read()`: one consistent CMOS read — waits out the update-in-progress flag (status reg A bit 7, bounded poll up to ~1 ms), captures all time registers, re-checks UIP to discard mid-read updates, converts BCD/12-hour encodings per status reg B, range-validates every field. `None` on timeout/garbage.
- `rtc::init()` takes the boot-time snapshot (called from `kernel_main_owned` right after PIT init: plain port I/O, thread context, interrupts still disabled, no locks held). `rtc::now()` extrapolates the snapshot with PIT ticks — `date` never re-reads the CMOS. The snapshot can later feed FAT32 timestamps (issue #14).
- Rules: thread context only, no locks, no heap, no ISRs — no interrupt handler may touch the CMOS, and callers must not hold other locks across `rtc::read()` (the UIP wait busy-polls).
- Shell: `date` prints `YYYY-MM-DD HH:MM:SS` (CMOS clock as-is, no timezone conversion).

**Task Scheduling** (`src/task.rs`, issue #18 stage 1 — cooperative, no preemption yet):
- `Task` = id + name + state (`Ready`/`Running`/`Exited`) + `extern "C" fn()` entry + an owned 64 KiB heap stack (`alloc_zeroed`, 16-byte aligned; freed by the scheduler's reaper once the task is `Exited` and some later `schedule()` runs from another stack). Table slot 0 is `main` — the kernel main loop itself, on the static kernel stack (`stacks.rs`), never started through the trampoline.
- A fresh task's initial context never returns into a caller: the switch's final `ret` lands in `task_trampoline`, which calls the entry and then `task::exit_current()`.
- Context switch (`global_asm!` `task_switch`): the `x86_64-unknown-uefi` target uses the **Microsoft x64 ABI** — args in `rcx`/`rdx`, non-volatile state is `rbx`, `rbp`, `rdi`, `rsi`, `r12`–`r15` AND `xmm6`–`xmm15` (the switch spills XMM to a 160-byte area below the saved RSP). Initial stack: trampoline address at the 16-byte-aligned top, zeroed integer registers below, so at trampoline entry RSP ≡ 8 (mod 16) exactly as after a `call`.
- `task::init()` runs in `kernel_main_owned` just before the shell; `spawn`/`schedule`/`yield_now` are thread-context only. `schedule()` disables interrupts across the decision + switch and preserves each caller's IF on resume — callable from the main loop (interrupts enabled) and the test harness (disabled). A FRESH task never runs that epilogue, so it inherits the scheduling context's IF via per-task `start_if`/`started` state applied by the trampoline: shell-spawned tasks run with IRQs on (a task entry MAY be interrupted — ISRs are plain handlers, nothing is scheduled from them), harness-driven tasks stay IF=0. Tasks must not yield while holding a lock another task can take (terminal, serial-TX, FS, heap, scheduler) — single-CPU deadlock. The main loop runs one `schedule()` round whenever `task::has_ready_tasks()`; otherwise `enable_and_hlt`.
- Shell commands: `tasks` (table dump, current task marked `*`) and `taskdemo` (spawns the demo suite and returns immediately — the tasks run from the main loop; the command never waits on them). Suite: `demo` prints 3 numbered lines across yields, `stress` yields 100 times, `counter` wakes once per round-robin round until stress finishes, and `sleeper` (shell path only — the harness must not spawn it, `sleep_ms` with IF=0 never wakes) blocks 250 ms on the IRQ-driven PIT, the live proof that shell-spawned tasks start with IRQs enabled. The same suite is asserted by the harness (`task_scheduler` test: 100 stress yields = 200+ context switches, counter must observe exactly 100 rounds, fresh tasks must have started with IF=0 to match the harness scheduling context, all tasks `Exited`, `main` still current).
- STAGE 2 GAP (not implemented): timer preemption on the PIT tick — requires spilling the full interrupt frame (volatile registers + RFLAGS) to the preempted task's stack; the cooperative switch only covers call-boundary yields. No userland.

**Memory** (`src/allocator.rs`, `src/memory.rs`):
- `src/main.rs` retains the memory map returned by `ExitBootServices()` (it is `'static`) and passes it to `kernel_main`.
- `src/memory.rs` (issue #5 stage 1): copies a compact summary of the firmware map into `MEMORY_SUMMARY` (`spin::Mutex` over a fixed 64-region static array; `phys_start`, `page_count`, memory type) and prints total usable RAM, region count, and free-frame count in the boot log. Regions starting above 4 GiB are ignored (and counted in the log).
- `src/memory.rs` also holds the physical frame allocator: `FRAME_ALLOCATOR: spin::Mutex<BitmapFrameAllocator>` over a static 128 KiB bitmap (1 bit per 4 KiB frame, low 4 GiB = 1,048,576 frames). The static is zero-filled (.bss — no EFI file cost); init marks every bit used, then clears the frames of CONVENTIONAL regions below 4 GiB. `allocate_frame() -> Option<u64>` returns identity-mapped physical addresses (no paging layer yet); `free_frame(addr)` clears the bit (callers must only free frames from `allocate_frame`; double frees are ignored). `allocate_contiguous(frames) -> Option<u64>` scans the bitmap first-fit for a run of `frames` consecutive free frames, marks them used, and returns the physical start address (`None` when the pool is too fragmented/short; O(FRAME_COUNT) worst case, allocation-free). Thread-context free-function wrappers: `memory::reserve_frames(frames)` and `memory::free_frame_count()`. A boot-time self-check in `memory::init` exercises both paths before anything reserves frames permanently.
- `src/allocator.rs`: heap = `linked_list_allocator::LockedHeap` (frees and coalesces), registered as `#[global_allocator]`. `init_heap_from_memory()` (called from kernel_main after `memory::init`) sizes the heap from CONVENTIONAL RAM: target = free conventional bytes / 8, clamped to [1 MiB, 32 MiB] and page-aligned, reserved as one contiguous run of frames via `memory::reserve_frames`; on a fragmented map the size halves down to 1 MiB. On success the reserved physical range (identity-mapped conventional RAM, RW|NX under W^X) is handed to `LockedHeap::init` and logged (`[heap] N MiB at 0x... (M frames reserved, X MiB free)`); the frames stay permanently out of the frame pool. If no contiguous 1 MiB exists anywhere, the static 1 MiB page-aligned .bss fallback (`HEAP_AREA`/`HEAP_SIZE`) is initialized instead — never a panic. `alloc` types (String, Vec, Box) are available throughout the kernel and deallocation reclaims memory — shell churn no longer leaks.
- Both `MEMORY_SUMMARY` and `FRAME_ALLOCATOR` are thread-context-only spin locks (single-core kernel; never take them from an ISR — if that ever changes, disable interrupts around the lock like `SCANCODE_QUEUE` takers do).
- The kernel owns its paging from `paging::init` (issue #5 stage 2): a static identity map in `.bss` (PML4 + PDPT + 6 PDs, 2 MiB pages, 0..6 GiB) replaces the firmware tables before any other init; CR3 is loaded there and the firmware CR3 stashed (`paging::old_cr3`). The kernel also switches off the firmware stack onto a kernel-owned guarded stack (`src/stacks.rs`) before frame distribution.
- W^X (stage 2b): EFER.NXE + PE section parsing. Every 2 MiB PDE overlapping the loaded image is split into 4 KiB PTs from a 16-entry pool — exec sections RX, writable sections RW|NX, read-only data + PE headers R|NX, in-image gaps RW|NX; all remaining flat leaves (RAM, framebuffer) are NX. A boot-time self-check rejects writable+executable leaves (`[pt] W^X verified` in the boot log). W^X is skipped as a whole if LoadedImage info is missing, PE headers fail validation, or the image needs more than 16 PTs (>32 MiB) — never half-applied.
- Limits: kernel RAM and page tables are all in the low-4-GiB LOADER_CODE region; the frame allocator pool stays <4 GiB (`memory::MAX_SUPPORTED_PHYS`); the map covers 0..6 GiB as headroom for non-relocating loaders. Stack regions have a 2 MiB unmapped guard half each; deliberate faults are exercised by controlled probes (`paging::guard_probe_addr`, `paging::wx_image`), not at runtime.

**Storage** (`src/drivers/`, issue #14):
- `src/drivers/pci.rs` (issue #23): legacy 0xCF8/0xCFC enumeration into a fixed static table (no heap, no ISR-shared lock, thread context only). Discovery is read-only; the only config-space write is `enable_device()` (RMW of the command register: I/O + memory decode + bus master — required before any driver touches BARs or DMA).
- `src/drivers/block.rs`: `BlockDevice` trait (512-byte sectors, read-only for now) + free functions `block::read_sectors(lba, count)` / errors forwarding to the single registered device. String errors to match the fs/shell `Result<_, String>` convention.
- `src/drivers/virtio_blk.rs`: virtio-blk over QEMU's **transitional legacy** PCI transport (1AF4:1001, virtio 0.9.5 register layout in the I/O-port BAR0). Deliberately NO modern-device support (1AF4:1042 needs an MMIO BAR mapping — reported clearly instead). Init sequence: reset → ACK|DRIVER → feature negotiation (host features read, BAD_FEATURE rejected, only VIRTIO_BLK_F_RO accepted back) → queue 0 (device-reported size, page-aligned physically-contiguous heap allocation for desc table + avail ring + used ring + one request's header/data/status, handed over as QUEUE_PFN) → capacity read → DRIVER_OK → one polled sector-0 verification read. Requests: 3-descriptor chain, avail ring publish, QUEUE_NOTIFY kick, **polled** used-ring completion (bounded spin, no IRQ routed, never from an ISR). DMA works with no bounce buffers because the heap is identity-mapped conventional RAM < 4 GiB (virtual == physical; x86 PCI DMA is cache-coherent); avail.flags = NO_INTERRUPT. The device object lives forever behind `BLOCK_DEVICE` (`spin::Mutex`, thread-context only); `Drop` returns the DMA region but never runs in practice.
- `make disk` creates the 64 MiB FAT32 image (`disk.img`, gitignored, persistent across runs; `mkfs.vfat` + `mcopy` from the Nix shell) and `run`/`run-no-kvm` attach it via `-drive if=none,id=disk0 -device virtio-blk-pci,drive=disk0` (default transitional device on the `pc` machine — do NOT add `disable-legacy=on`, that forces the modern device this driver doesn't support).
- Shell commands: `disks` (PCI virtio-blk + capacity + mounted volume summary), `diskread <sector>` (hex dump of one sector), `fatls [path]`, `fatcat <file>` (read-only FAT32 below).

**Filesystem** (`src/fs/`):
- `mod.rs` defines a `FileSystem` trait and a global `FILESYSTEM: Mutex<Box<dyn FileSystem>>` behind free-function wrappers (`fs::read_file`, `fs::list_directory`, etc.) used by the shell.
- `memory.rs` is the active implementation: a RAM tree seeded with `/bin`, `/home`, `/etc`, and `README.txt`.
- `fat32.rs` (issue #14): a real read-only FAT32 driver over `block::read_sectors` — NOT an implementation of the `FileSystem` trait and NOT the global `FILESYSTEM` (that stays the RAM tree behind `ls`/`cd`/`cat`). Mount (`fs::fat32::mount()`, from the boot sequence after virtio-blk init) detects a superfloppy (sector 0 = boot sector, what `mkfs.vfat` produces) or an MBR with a FAT32 partition (types 0x0B/0x0C), validates the BPB (512-byte sectors, power-of-two cluster, sane FAT size/root cluster), and exposes `list`/`read_file` through the `FAT32` spin lock. Read path: FAT chain walk (one cached FAT sector, loop-capped), directory parsing with 8.3 short names (NT lowercase flags honored) and LFN assembly (sequence order + checksum over the short entry's name bytes — the checksum is `sum = rot_right1(sum) + byte`, and the fragments carry it in their byte 13), path resolution from the volume root (no persistent FAT cwd), zero-length files legal. Write support: not implemented.

**ACPI / Power** (`src/acpi.rs`, issue #12):
- The RSDP physical address is captured from the UEFI configuration table BEFORE `ExitBootServices()` (`kernel::AcpiInfo` in `BootArgs`); `acpi::init(rsdp)` runs right after `paging::init` — tables are identity-mapped, so parsing uses raw unaligned loads, no heap, no locks (parsed state lives in a `spin::Once`, written once, read-only afterwards).
- `init` walks RSDP → XSDT (8-byte entries, preferred on RSDP rev ≥ 2) / RSDT (4-byte entries) → FADT (`FACP`), validating signature, length bounds (≤ 1 MiB cap so a corrupt length can't walk the checksum off the identity map), and checksums at every step. It stores PM1a/PM1b_CNT_BLK (FADT +0x40/+0x44) and, when the FADT is ≥ 0x84 bytes, the RESET_REG GAS (+0x74) / RESET_VALUE (+0x80).
- Any malformed table only disables ACPI power control — never panics. Missing/invalid RSDP/FADT → shutdown halts, reboot uses the 8042 controller (status-wait, then 0xFE to port 0x64).
- `shutdown` writes `SLP_TYPa << 10 | SLP_EN` (16-bit) to PM1a_CNT_BLK, then PM1b with SLP_TYPb = 0. LIMITATION: the DSDT `\_S5` AML package is NOT parsed, so the SLP_TYP value is hardcoded to 0 — the value QEMU's generated DSDT declares (verified by dumping the guest DSDT via the QEMU monitor). Vendor firmware defines its own values and may need a different one. Generic `\_S5` AML parsing remains to be implemented (needs a minimal AML interpreter — candidate follow-up issue).
- `reboot` writes RESET_VALUE to the FADT reset register (I/O or volatile MMIO) when present, then falls back to the 8042 `0xFE` reset, then halts.
- QEMU note: OVMF + QEMU here publish an RSDP rev 2 with an XSDT whose FADT is rev 1 (116 bytes) — no RESET_REG, PM1a_CNT_BLK = 0xb004 — so the boot log shows `reset reg: none (8042 fallback)` and shutdown goes through PM1a S5. This is the expected log, not a parse failure.

**Shell & I/O**:
- `src/serial.rs`: 16550 COM1 driver — polled TX, IRQ4-driven RX (issue #21: IER bit0, PIC master mask 0xEC). ALL terminal output is mirrored to serial (serial lock taken before, never nested with, the terminal lock), so QEMU's `-serial stdio`/`-serial file:` captures the boot log and entire shell session — the primary debugging channel; with RX enabled, `-serial stdio` is also a full headless input path. The TX/print lock is thread context + panic path only; never from ISRs. Received bytes go into a 256-byte ring queue (`RX_QUEUE`) pushed by the IRQ4 handler (UART LSR/RBR reads only — no TX lock, no allocation, no console output); the main loop pops it with `try_pop_input` (interrupts disabled) and decodes bytes with `serial::handle_input`: printable ASCII → `Char`, CR → `Enter`, LF → `Enter` only when the previous byte wasn't CR (CRLF-safe), `0x7F`/`0x08` → `Backspace`, `0x03` → `CtrlC`, `0x0C` → `CtrlL`, other control bytes ignored.
- `src/shell.rs`: Command parsing, history (10 entries), built-ins (help, echo, version, uptime, sleep, date, reboot, ...) and filesystem commands (ls, cd, pwd, cat, mkdir, rm, write), storage commands (disks, diskread; fatls, fatcat for the read-only data disk). Global singleton behind `spin::Mutex` — command handlers run in the kernel main loop (thread context), fed `keyboard::KeyEvent`s one at a time from the keyboard scancode queue and the COM1 serial RX queue.
- Shell line editing (issue #8): `handle_key_event` maintains a byte-index `cursor_position` (commands are ASCII), inserting chars mid-line and redrawing via `terminal::redraw_input`. Left/Right/Home/End move the cursor; Backspace/Delete remove before/at it; chars typed at the end of the line echo directly (serial-visible), everything else only redraws the framebuffer. `Up`/`Down` walk the history (index starts at `history.len()`); the first `Up` from a fresh line saves the buffer into `draft`, which `Down` restores when navigating past the newest entry. Executing a command or Ctrl+C resets index/draft; Ctrl+C prints `^C` + fresh prompt, Ctrl+L clears the screen and redraws any pending input. Rendering state (`input_start_y`, `rendered_cells`) is captured in `print_prompt` so redraws clear exactly what was on screen.
- `src/terminal.rs`: Framebuffer text terminal (8x8 font from `src/font.rs`, direct pixel writes). Pixel values are produced by `kernel::encode_pixel(&PixelFormat, color)` — colors are 0x00RRGGBB and are converted per GOP format (Bgr written as-is, Rgb swaps R/B, Bitmask aligns/scales each channel to its mask, zero masks contribute nothing; BltOnly never reaches the kernel). All framebuffer accesses are volatile (`write_volatile`/`read_volatile` per u32) because paging maps the framebuffer UC. Scrolling shifts the framebuffer up one text row (10 px) via `KernelGraphics::scroll_up` (volatile per-pixel move) and clears only the exposed bottom row. `terminal::redraw_input(prompt, buffer, cursor_pos, start_y, previous_cells)` redoes the shell input line in place without ANSI escapes: clears `max(previous_cells, prompt.len()+buffer.len())` cells from `(0, start_y)` via `write_char`, redraws prompt + buffer, and parks the cursor at `prompt.len()+cursor_pos` (row/col via `self.cols`; `start_y` clamped to the last row if output scrolled). Redraws are thread context and not mirrored to serial.
- `src/keyboard.rs`: Scancode set 1 + 0xE0-prefixed extended codes → `KeyEvent` (`Char(c)`, `Enter`, `Backspace`, `Delete`, `Up/Down/Left/Right`, `Home/End`, `CtrlC`, `CtrlL`), tracks Shift + left/right Ctrl. The `extended` flag consumes fake shifts (E0 2A/36/AA/B6 → ignored, no shift-state change); E0 1D/9D track right Ctrl; extended break codes produce no event. Non-extended 0x48/50/4B/4D/47/4F/53 map to the same navigation events (NumLock caveat: with NumLock off real keyboards send digits there; QEMU defaults to NumLock on). Ctrl+<char> yields events only for C and L.

**Test Harness** (`src/test_harness.rs`, cargo feature `test-harness`, issue #13):
- Only compiled with `--features test-harness` (`make test`); normal builds are unchanged. In test builds `kernel_main` calls `test_harness::run()` right after `fs::init()` and BEFORE `interrupts::enable()`, so the harness never touches the shell, the scancode queue, or any IRQ path, and runs with interrupts still disabled.
- Eight deterministic tests: heap churn (allocate/verify/drop `Vec`s and `String`s of varied sizes over the linked-list heap), frame-allocator invariants (3 frames: 4 KiB alignment, distinct, < 4 GiB, free count restored), FS CRUD (create/read/overwrite/delete `/harness.txt`, mkdir/rmdir lifecycle incl. non-empty rmdir rejection), path normalization (`cd` with `..`, `//`, trailing `/`, `..` past root; rmdir of the cwd rejected), error formatting (missing paths give non-empty messages naming the path), keyboard decode (pure `Keyboard` state machine: E0-prefixed arrows/Home/End/Delete/keypad Enter, fake shifts don't stick, Ctrl+C/Ctrl+L, extended release codes ignored), framebuffer format encoding (pure `kernel::encode_pixel` on `kernel::PixelFormat`: Bgr written unchanged, Rgb swaps R/B, Bitmask with 8-bit, 5/6/5, and zero-width masks), and the task scheduler (spawns the `task::demo` suite with interrupts still disabled, drives ~100 rounds of `task::schedule()`, and asserts the stress/counter/demo counters — 100 yields = 200+ context switches through the MS-x64 switch — plus `Exited` states and `main` still current). Each test prints `[PASS]`/`[FAIL]` (mirrored to COM1) and returns a `Result` so one failure doesn't halt the rest; no `assert!` panics, no keyboard/QMP dependency.
- Exit path: writes 0x10 (pass) or 0x11 (fail) to isa-debug-exit port 0xF4 → QEMU exit `(value << 1) | 1` = 33 or 35; `make test` treats 33 as success and everything else (including 60 s timeout) as failure.

### Module Dependencies & Conventions
- All interrupt handlers must use `extern "x86-interrupt"` ABI
- Everything the kernel needs from firmware must be captured before `ExitBootServices()`: the GOP pixel format and bitmask masks (`kernel::PixelFormat`; the kernel refuses to boot in Blt-only modes), the loaded-image bounds (`kernel::ImageInfo`), and the ACPI RSDP address from the config table (`kernel::AcpiInfo`) — the config table is unreachable after EBS
- All static mutable state is guarded with `spin::Mutex` (+ `lazy_static`). The only locks shared between ISR and thread context are `SCANCODE_QUEUE` in `src/keyboard.rs` and the serial `RX_QUEUE` in `src/serial.rs`; thread-side takers must disable interrupts around them. Never call into `TERMINAL`, `SHELL`, `FILESYSTEM`, or the allocator from an interrupt handler — that reintroduces the single-core deadlock this design removed (issue #2). The task scheduler lock (`SCHEDULER` in `src/task.rs`) is thread-context ONLY — never from an ISR; `schedule()` itself disables interrupts across the decision + context switch. Task entries run in thread context and may use the terminal, serial, FS, and the heap, but must never call into the shell or take `SHELL`; a task that panics is fatal (panic = abort, no task teardown).
- Version comes from `Cargo.toml` alone (`env!("CARGO_PKG_VERSION")`, expanded at compile time — safe before the heap is up): kernel boot banner and the shell `version` command print `ilo-lawa OS v<version>`, the shell banner prints `ilo-lawa Shell v<version>`. Never hardcode version literals in source.
- The release build is warning-free (issue #15). Keep it that way: fix warnings at the root; targeted allowances with an issue reference are the only acceptable form.

Work is tracked as GitHub Issues on `hnkNkm/ilo-lawa` (`gh issue list`), labeled P0-critical through P3-low. The issue set came from a full gap analysis (2026-07); check it for known limitations before filing new ones.

## Common Issues and Solutions

- **Crashes after enabling interrupts**: Check GDT segment selectors, ensure all segments are properly initialized
- **Double faults**: Verify IST stack is properly allocated and TSS is loaded
- **Keyboard not working**: Ensure PIC mask enables IRQ1, check EOI is sent properly
- **Allocation failures / panics in shell commands**: the heap is sized from conventional RAM at boot (free/8 clamped to [1 MiB, 32 MiB]; the `[heap]` boot-log line shows the size and reserved frames). If commands OOM, look for leaked allocations first; then raise `MAX_HEAP_SIZE` in `src/allocator.rs` or check the frame pool wasn't pre-drained before `init_heap_from_memory()` (a `[heap] no contiguous run` log line means the static 1 MiB fallback engaged)
- **Build failures**: Always build inside `nix develop --impure`
